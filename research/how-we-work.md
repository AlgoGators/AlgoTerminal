# How we work here

The rules of engagement, so that a false result cannot quietly become a
believed one. Nothing in this file is a performance figure. Figures are
generated by the scripts and are never copied into prose.

## The principle

Every failure mode this project hit was catchable by a machine check. So the
checks are code, not habits. Habits failed. Automation held.

## The gates

Run `python scripts/gates.py` before any claim. Hard gates must pass.

1. **Causality.** Every transform is recomputed from data truncated at `t` and
   compared with the value used at `t`. If they differ, the transform uses
   future information. This kills the whole lookahead class.
2. **Data artifact.** Each research panel is scanned for scheduled
   discontinuities (a calendar jump that is consistently signed across years,
   which is the signature of a contract roll), implausible moves, and missing
   data. The raw front-month futures panel fails this gate by design; the
   roll-free spot panel passes.
3. **Trial counter.** `scripts/trials.py` counts every configuration
   evaluated. The multiple-testing correction reads that number. It only
   grows. Call `trials.bump()` for each new evaluation.
4. **Cost ladder.** A result is reported at the measured cost and at twice
   the measured cost. A result that does not survive double cost is not a
   result.
5. **Negative control.** Every result must fail on a shuffled or shifted
   control. If the shuffled version performs the same, the result is an
   artifact of the construction.

`python scripts/gates.py --self-test` proves the gates bite, by running them
against a known non-causal transform and the known-contaminated panel.
`python scripts/audit_invariants.py` re-checks the corrected defects and runs
the two hard gates.

## Working rules

- **One pipeline.** One panel builder, one engine, one cost model, one
  metrics function. No parallel implementations. If a formula appears twice,
  delete one.
- **Pre-register.** No experiment runs without a written hypothesis, a stated
  evaluation window, and a kill rule.
- **The evaluation window is a budget.** Each look spends information. Freeze
  a large segment and unlock it once, for a decision.
- **Point-in-time data only.** A value used at `t` must have been public at
  `t`. Publication lag and revisions both count.
- **The tradeable object.** Prices must be the thing you would actually
  trade. A derived spread built from independently rolled series is not it.
- **Reproducible per experiment.** Commit inputs by hash, the config, the
  output, and the trial increment. Rebuild from raw data and diff before
  trusting a result.
- **Re-audit on a schedule.** Assume drift. Run the gates and a from-scratch
  rebuild.

## What counts as evidence

In-sample improvement is not evidence and never was. A claim needs a
pre-registered, cost-inclusive, trial-adjusted result that clears a stated
bar on a frozen out-of-sample segment, and then clears it again forward. The
bar is set before the search, not after.

## Kill discipline

Write the kill rule before the work. Most lines of research will fail; the
process must make failing cheap and visible, and succeeding hard to fake. A
clean "no" is a result. A tuned "yes" is not.
